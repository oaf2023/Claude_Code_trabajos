## Objetivo

Archivo local de Firebase CLI que asocia el directorio del proyecto con el proyecto Firebase por defecto, de modo que los comandos `firebase use`/`firebase deploy`/`firebase emulators:start` operen sin especificar `--project` cada vez.

FUNCIONALIDAD EXISTENTE. El proyecto por defecto coincide con el identificador del proyecto Firebase usado en el resto de la configuración (ver `google-services.json.md`). [NIVEL DE CERTEZA: Confirmado por código]

**Explicación de las líneas 1–5:**

- **Línea 2**: sección `projects`.
- **Línea 3**: `default` fija el proyecto Firebase activo por defecto para este directorio. Todos los comandos de Firebase CLI sin `--project` explícito apuntarán a ese proyecto (producción), lo que exige cuidado para no desplegar reglas/funciones de prueba sobre producción.
- **Líneas 4-5**: cierre del objeto.

## Observaciones técnicas

- [NOTA] Al estar versionado en el repositorio, el archivo fija un único proyecto por defecto para todo el equipo; si existen proyectos de staging/desarrollo, se sugiere no depender solo de `firebase use` manual.
- [OBSERVACIÓN TÉCNICA] El identificador aquí debe ser consistente con el `project_id` de `google-services.json` y con el bucket de Storage usado en runtime; una divergencia rompería reglas/deploys o apuntaría a otro entorno.

## Seguridad

- [BAJO] El proyecto por defecto apunta al entorno real de producción: un `firebase deploy` accidental (sin revisión de `--only`/`--project`) publicaría reglas o funciones directamente en producción. En entornos con staging, conviene separar proyectos y documentar el flujo.
- [INFORMATIVO] El identificador de proyecto no es una credencial por sí mismo, pero forma parte de la superficie de identificación del backend; se documenta como [SECRETO OCULTO] por política.

## Riesgos y recomendaciones (sin modificar código)

- [RECOMENDACIÓN] Revisar antes de cada `firebase deploy` el alcance (`--only firestore:rules`, `--only functions`, etc.) y el proyecto destino.
- [RECOMENDACIÓN] Considerar un proyecto Firebase separado para desarrollo/staging si aún no existe, evitando desplegar reglas de desarrollo sobre el entorno de producción.
