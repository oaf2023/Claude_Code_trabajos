## Objetivo

Pipeline de **integración continua** de GitHub Actions con dos trabajos:

1. `lint-typecheck-test`: validaciones de calidad (typecheck de app y functions, lint, tests y auditoría de dependencias) tras cada push a `main`/`develop` y en pull requests hacia `main`.

**Explicación de las líneas 1–11:** define identidad y disparo del workflow.

- **Línea 1** (`name: CI`): nombre visible del workflow.
- **Línea 3** (`on:`): disparadores.
- **Líneas 4–5** (`push: branches: [main, develop]`): corre en cada push a `main` y `develop`.
- **Líneas 6–7** (`pull_request: branches: [main]`): corre en PRs dirigidas a `main`.
- **Líneas 9–11** (`concurrency: group ... cancel-in-progress: true`): por workflow y rama/ref; si llega una ejecución nueva sobre la misma ref, cancela la anterior. Patrón correcto para ahorrar minutos de Actions.

### Bloque 2 (líneas 13–50): trabajo lint-typecheck-test

```yaml
jobs:
  lint-typecheck-test:
    runs-on: ubuntu-latest
    timeout-minutes: 15

    steps:
      - uses: actions/checkout@v4

      - uses: actions/setup-node@v4
        with:
          node-version: 20
          cache: npm
          cache-dependency-path: |
            package-lock.json
            functions/package-lock.json

      - name: Install dependencies (app)
        run: npm ci

      - name: Install dependencies (functions)
        working-directory: functions
        run: npm ci

      - name: Typecheck (app)
        run: npx tsc --noEmit

      - name: Typecheck (functions)
        working-directory: functions
        run: npx tsc --noEmit

      - name: Lint
        run: npx eslint . --ext .ts,.tsx --max-warnings 50 || true

      - name: Test
        run: npx jest --passWithNoTests

      - name: Audit
        run: npx npm audit --audit-level=high || echo "Moderate vulns only — acceptable"
```

### Bloque 3 (líneas 52–87): trabajo build-android

```yaml
  build-android:
    runs-on: ubuntu-latest
    timeout-minutes: 30
    needs: lint-typecheck-test

    steps:
      - uses: actions/checkout@v4

      - uses: actions/setup-node@v4
        with:
          node-version: 20
          cache: npm

      - name: Install dependencies
        run: npm ci

      - name: Generate google-services.json
        env:
          GOOGLE_SERVICES_JSON: ${{ secrets.GOOGLE_SERVICES_JSON }}
        run: echo "$GOOGLE_SERVICES_JSON" > android/app/google-services.json

      - name: Setup JDK 17
        uses: actions/setup-java@v4
        with:
          distribution: temurin
          java-version: 17

      - name: Build Android APK
        working-directory: android
        run: ./gradlew assembleDebug --no-daemon

      - name: Upload APK
        uses: actions/upload-artifact@v4
        with:
          name: app-debug
          path: android/app/build/outputs/apk/debug/app-debug.apk
```

**Explicación de las líneas 52–87:** compila el APK debug con Firebase habilitado y lo sube como artefacto.

- **Líneas 60–63** (`actions/setup-node@v4`): Node 20 y caché npm (sin `cache-dependency-path`: usa el lockfile de la raíz).

## Observaciones técnicas

- [OBSERVACIÓN TÉCNICA] Línea 44: `npx eslint . ... || true` desactiva la puerta de lint: los errores de ESLint **no** rompen el CI. Además, `--max-warnings 50` es inocuo porque el código de salida se ignora. Impacto potencial: regresiones de estilo/calidad llegan a `main`. [NIVEL DE CERTEZA: Confirmado por código]
- [OBSERVACIÓN TÉCNICA] Línea 50: `npx npm audit --audit-level=high || echo "Moderate vulns only — acceptable"` desactiva la puerta de auditoría **y** imprime un mensaje engañoso: el audit con `--audit-level=high` solo devuelve código distinto de cero cuando hay vulnerabilidades high/critical, así que el mensaje "solo vulnerabilidades moderadas — aceptable" se muestra precisamente cuando hay vulnerabilidades altas. Impacto potencial: dependencias vulnerables pasan desapercibidas. [NIVEL DE CERTEZA: Confirmado por código]
- [OBSERVACIÓN TÉCNICA] Líneas 52–87: el trabajo `build-android` asume que la carpeta `android/` existe en el checkout, pero `.gitignore` la excluye (`/android`, línea 55 del `.gitignore`) y el workflow **no ejecuta `expo prebuild`** para generarla. En repositorios clonados/commit desde Windows puede faltar el bit y el paso falla con "Permission denied"; mitigación habitual: `chmod +x gradlew` previo o usar `bash gradlew`. No verificable aquí. - [BAJO] Pinning de acciones por SHA ausente (tags `v4` mutables): mitigar con SHA o con confianza en los mantenedores oficiales de GitHub.
- [MEDIO] Líneas 68–71: manejo del secreto `GOOGLE_SERVICES_JSON` por `echo` multilínea: aunque GitHub enmascara secretos en los logs, el patrón puede filtrar contenido si el secreto contiene líneas que coincidan parcialmente con el patrón de enmascarado; recomendado escribir el archivo desde el entorno sin pasar por el shell o usar base64. El archivo `google-services.json` contiene claves API de Firebase (no credenciales de servidor) y queda además embebido en el APK debug subido como artefacto (comportamiento esperado de Firebase).
- [INFORMATIVO] No se imprimen otros secretos; no hay credenciales de firma en el CI (la firma release es manual y local).
- [INFORMATIVO] El APK debug subido como artefacto incluye la configuración Firebase; es un binario de depuración sin firmar apto solo para pruebas internas.
