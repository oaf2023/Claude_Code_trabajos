SafeAlert es una aplicación móvil de seguridad personal con detección de voz offline, alertas SOS, geolocalización en tiempo real, y un sistema de suscripciones vía Mercado Pago. Construida con React Native + Expo Router + TypeScript y backend Flask + PythonAnywhere + Firebase. Incluye PWA instalable para móviles.

Estado del Desarrollo

  • Completado Fase 0 — Seguridad: Firebase Auth en backend, rotación de API keys
  • Completado Fase 1 — Core SOS: AlertStateMachine, AlertQueue, DeviceDiagnostic
  • Completado Fase 2 — Calidad: CI pipeline, Sentry crash reporting, Runbooks
  • Completado Fase 3 — Producto: Historial de alertas, WCAG accesibilidad
  • Completado Fase 4 — Privacidad: PrivacyService, exportación/eliminación de datos
  • Completado Fase 5 — Arquitectura: i18n (retirado como código muerto), AccountService, Cloud Run
  • Completado Fase A — PWA móvil real, typecheck 9→0, endpoints faltantes, seguridad IDOR

Flujo de Alerta SOS

WakeWordService → AlertService.send() → AlertStateMachine (locating) → GPS + ubicación → Firestore (alerta) → AlertQueue (cola persistente) → Firebase Function → Twilio SMS a contactos

Almacenamiento

Firestore

Usuarios, contactos, alertas, settings. Tiempo real vía onSnapshot. Reglas por userId.

SQLite (PythonAnywhere)

Contactos de emergencia, período de prueba, pagos, tickets. Dos bases: safealert.db y safealert_tel.db.

AsyncStorage

Persistencia de Zustand stores: settings, guard-storage, alert-machine-storage. Cola de alertas offline.

15. Seguridad y Privacidad

Firebase Auth

Autenticación anónima con migración a cuenta recuperable (email+password) vía AccountService. Tokens verificados en backend con Firebase Admin.

API Keys

Rotación completa de AUDIO_ALERT_API_KEY. Clave interna SAFEALERT_INTERNAL_KEY para pagos. Comparación HMAC en todas las verificaciones.

Sentry

Redacción automática de: headers Authorization/X-API-Key/X-Internal-Key, tokens en breadcrumbs, datos de request.

Privacidad (Fase 4)

5 tipos de consentimiento (location, audio, contacts, notifications, analytics) con grant/revoke. Exportación JSON de datos. Eliminación total de cuenta.

Almacenamiento

SecureStore para datos sensibles (con fallback AsyncStorage). Sin secretos en frontend. Firestore rules por userId.

Validación

Regex en device_id (path traversal). Rate limiting SQLite compartido entre workers (30 req/60s, Fase C). Firma HMAC en webhooks MP. Borrado lógico en contactos.

Mejoras de Seguridad (Fases A-C)

  • require_firebase_auth implementado de verdad (antes declarado pero no aplicado) — verifica ID token con Firebase Admin en register/status.
  • require_admin_key en /api/v1/ubicaciones/ultima/:id — cerrado IDOR que exponía la última ubicación de cualquier usuario.
  • Endpoints faltantes creados: /api/tickets/create y /api/internal/link-preapproval (la app los llamaba y recibía 404).
  • Privacidad de persistencia (DAMA-DMBOK): useAlertMachineStore ya no persiste teléfonos ni coordenadas en AsyncStorage plano.
  • Falsa confirmación de pago corregida: PaymentModal.handleConfirmPayment ya no llama onSuccess() en el catch.
